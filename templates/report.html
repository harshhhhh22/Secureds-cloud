3. Understand your files

Common project files and what they normally do. The exact purpose of a file depends on its contents.

app.py

Often the main entry point of a Python web application. It may define routes and connect application components.

auth.py

Often contains login, logout, registration, or permission-related logic.

requirements.txt

Lists Python packages the project depends on. Pinning versions helps make installations more predictable.

.env

Often stores private configuration such as secret keys. Do not publish real secrets or commit this file to version control.

tests/

Usually contains automated tests that check whether parts of the application behave as expected.

.github/workflows/

Can contain GitHub Actions automation for running tests, checking code, and performing deployment tasks.

README.md

Usually explains the project's purpose, setup instructions, and how to run it.

.gitignore

Tells Git which files should normally be left out of version control, such as local environments and secret files.

These are general examples, not confirmation that every listed file exists in your uploaded project. The next improvement will connect this section to the actual file inventory discovered in your ZIP.
